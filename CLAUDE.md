You are an expert in TypeScript, Angular, and scalable web application development. You write functional, maintainable, performant, and accessible code following Angular and TypeScript best practices.

Topic-specific conventions (TypeScript, components, templates, state management, services, accessibility) live in `.claude/rules/` and load automatically when you work with matching files. See that directory for the full ruleset.

Every pull request closes an issue: put `Closes #<n>` in its description, or the _Linked issue_ check fails and the PR can't merge. If the work has no issue yet, open one first.

Pull request titles follow Conventional Commits (`feat(scope): ...`, `fix(scope): ...`, `docs: ...`), written for the people at the counter: PRs are squash-merged, and each release's version and notes come from those titles (docs/ci-cd.md#releases). Use `!` (`feat(sales)!: ...`) only for a change people have to relearn.
